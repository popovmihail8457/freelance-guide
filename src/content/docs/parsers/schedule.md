Парсер часто нужен не один раз, а регулярно: раз в час, день, неделю.

## Варианты запуска

| Где | Чем |
|---|---|
| Свой компьютер Windows | Планировщик заданий |
| Linux-сервер | cron или systemd timer |
| Без сервера | GitHub Actions по расписанию |

## Порядок работы

1. Сделайте так, чтобы скрипт запускался одной командой.
2. Пишите лог в файл: что запущено, сколько собрано, какие ошибки.
3. Добавьте уведомление об ошибке (например, сообщение в Telegram).
4. Проверьте повторный запуск: не должно быть дублей.

## Типичные ошибки

- Нет лога - непонятно, почему не сработало.
- Запуск зависит от открытого терминала.
- Перезапись старых результатов без сохранения истории.

## Чек-лист
